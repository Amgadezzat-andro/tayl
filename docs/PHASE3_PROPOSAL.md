# مقترح المرحلة 3 — المحرك المحاسبي: القيود اليومية والأستاذ العام

**الحالة:** مقترح للمراجعة — **لم يبدأ التنفيذ.** · **التاريخ:** 2026-11-10 · **الأساس:** الإصدار 0.3.1 · **الإصدار المستهدف:** 0.4.0

## 1. الهدف

بناء القلب المحاسبي الذي ستبني عليه كل المراحل التالية: **قيد يومي يُرحَّل إلى أستاذ عام لا يُعدَّل**، عبر **محرك ترحيل واحد** ستستخدمه لاحقًا الفواتير والتحصيلات والمخزون دون تكرار قواعد الترحيل. وتشمل المرحلة: ترقيم المستندات، والأرصدة الافتتاحية، والقيد العكسي، وثلاثة استعلامات أساسية (دفتر اليومية، كشف الحساب، ميزان المراجعة).

**خارج المرحلة** (التفصيل في القسم 11): العملاء والموردون، التحصيل والسداد، الفواتير، المخزون، قيد الإقفال السنوي، فروق العملة، القوائم المالية النهائية.

## 5. تصميم قاعدة البيانات

كل الجداول `STRICT`، وكل القيم العشرية نصوص قانونية بالنمط الإلزامي في `DECIMAL_ENGINE.md` (لا REAL ولا SUM). الترحيلات الجديدة:
`numbering/0001_document_series.sql` · `chart-accounts/0002_posting_policy.sql` · `journal/0001_journal_ledger.sql`.

### 5.1 العلاقات الأساسية

```
branches ◄──────────────┐
fiscal_periods ◄────────┤
currencies ◄────────────┤
exchange_rates ◄────────┤ (rate_id: لقطة للتتبع فقط)
document_series ◄───────┤
                        │
                journal_entries ──1:N──► journal_lines ──► accounts
                  │  ▲                         │        └► cost_centers
                  │  └── reverses_id (1:1)     │
                  │                            │ عند الترحيل
                  └──── source ───────────────►▼
                                         gl_entries ──► accounts, cost_centers, branches,
                                       (الأستاذ العام)    fiscal_periods, currencies
```

**لماذا جدولان (`journal_lines` و`gl_entries`)؟** القيد اليومي مستند من عشرات المستندات القادمة؛ الفاتورة لن يكون لها «سطور قيد» بل سطور أصناف. الأستاذ هو المكان الوحيد الذي تُرحَّل إليه كل المستندات بشكل موحد، والتقارير تقرأ منه وحده. هذا يمنع أن يكتب كل نوع مستند تقاريره الخاصة.

### 5.2 `numbering`

```sql
document_series (
  id, code TEXT UNIQUE,                 -- 'JV', 'OB' ...
  doc_type TEXT NOT NULL,               -- 'journal' | 'journal_opening' | (لاحقًا: sales_invoice ...)
  name_ar, name_en,
  prefix TEXT NOT NULL,                 -- يُقفل بعد أول رقم
  per_branch INTEGER 0/1, reset_yearly INTEGER 0/1, padding INTEGER 4..10,
  is_default INTEGER 0/1,               -- سلسلة افتراضية واحدة لكل doc_type (فهرس فريد جزئي)
  is_active, created_at, updated_at)

document_counters (
  series_id → document_series, branch_id INTEGER NOT NULL DEFAULT 0, fiscal_year_id INTEGER NOT NULL DEFAULT 0,
  last_value INTEGER NOT NULL CHECK (last_value >= 0),
```

بيانات مرجعية: `JV` (قيود يومية) و`OB` (أرصدة افتتاحية) و`RV` (قيود عكسية)، قابلة للتعديل قبل الاستخدام.

### 5.4 `journal`

```sql
journal_entries (
  id INTEGER PRIMARY KEY,
  branch_id        → branches NOT NULL,
  entry_type       TEXT CHECK IN ('general', 'opening', 'reversal'),   -- 'closing' يُضاف بترحيل لاحق
  status           TEXT CHECK IN ('draft', 'posted'),
  entry_date       TEXT date,
  series_id        → document_series,
  number           TEXT UNIQUE,            -- NULL في المسودة؛ يُمنح عند الترحيل
  fiscal_period_id → fiscal_periods,       -- يُحدَّد عند الترحيل
  currency_id      → currencies NOT NULL,
  rate             TEXT NOT NULL,          -- '1' للعملة الأساسية
  rate_source      TEXT CHECK IN ('base', 'table', 'manual'),
  rate_id          → exchange_rates NULL,  -- السطر الساري وقت الترحيل (للتتبع)
  decimal_snapshot TEXT,                   -- JSON: سياسة الدقة وقت الترحيل
  total            TEXT, total_base TEXT,  -- مجموع المدين (= الدائن) بالعملتين
  description      TEXT NOT NULL, reference TEXT,
  reverses_id      → journal_entries UNIQUE,   -- القيد يُعكس مرة واحدة فقط
  reason           TEXT,                       -- إلزامي للعكسي
  created_by, created_at, updated_by, updated_at, posted_by, posted_at,
  CHECK ((status = 'draft') = (number IS NULL)),
  CHECK ((entry_type = 'reversal') = (reverses_id IS NOT NULL)),
  CHECK (entry_type <> 'reversal' OR length(trim(reason)) BETWEEN 3 AND 500))

journal_lines (
  id, entry_id → journal_entries ON DELETE CASCADE, line_no,
  account_id → accounts, cost_center_id → cost_centers NULL, description TEXT,
  debit TEXT NOT NULL DEFAULT '0', credit TEXT NOT NULL DEFAULT '0',      -- بعملة القيد، موجبة
  debit_base TEXT, credit_base TEXT,                                     -- تُحسب عند الترحيل
  UNIQUE (entry_id, line_no),
  CHECK ((debit = '0') <> (credit = '0')),                               -- طرف واحد فقط
  CHECK (debit NOT GLOB '*-*' AND credit NOT GLOB '*-*'))

gl_entries (                                   -- الأستاذ العام: إضافة فقط
  id, source_type TEXT NOT NULL,               -- 'journal' (لاحقًا: 'sales_invoice' ...)
  source_id INTEGER NOT NULL, source_line_id INTEGER, doc_number TEXT NOT NULL,
  posting_date, fiscal_period_id, branch_id, account_id, cost_center_id, currency_id,
  debit TEXT, credit TEXT,                     -- بالعملة الأساسية (ما تقرؤه التقارير)
  debit_fc TEXT, credit_fc TEXT,               -- بعملة المستند
  description, posted_by, posted_at)
```

**الحماية في القاعدة نفسها (triggers):**
- `journal_entries`: لا تعديل ولا حذف لقيد `posted`؛ الانتقال الوحيد المسموح `draft → posted` مرة واحدة.
- `journal_lines`: لا إضافة ولا تعديل ولا حذف لسطور قيد مرحّل.
- `gl_entries`: لا تعديل ولا حذف إطلاقًا.
- حذف مسودة مسموح (لم تُرقَّم ولم تؤثر على الأستاذ) مع حدث تدقيق.

**الفهارس:** `gl_entries (account_id, posting_date)`، `(branch_id, posting_date)`، `(cost_center_id, posting_date)`، `(source_type, source_id)`؛ `journal_entries (status, entry_date)`، `(branch_id, entry_date)`.

## 6. قواعد العمل

### 6.1 دورة القيد
`مسودة` (تُعدَّل وتُحذف بحرية، بلا رقم) ← `ترحيل` (رقم + أستاذ + قفل نهائي) ← عند الخطأ: `قيد عكسي` مرتبط بسبب، ثم قيد صحيح جديد.

### 6.2 قواعد الترحيل (محرك واحد لكل المستندات)
كلها داخل **معاملة واحدة** تشمل: التحقق، الرقم، تحديث القيد، سطور الأستاذ، التدقيق. أي فشل ⇒ لا شيء يُحفظ ولا رقم يُستهلك.
1. سطران على الأقل، وكل سطر طرف واحد بمبلغ موجب معتمد بسياسة عملة القيد.
2. الحساب تفصيلي نشط (`assertPostable`)، ويقبل القيد اليدوي إن كان المصدر قيدًا يدويًا.
3. مركز التكلفة حسب سياسة الحساب، ونشط، وتفصيلي، وفرعه (إن وُجد) = فرع القيد.
4. الفرع ضمن نطاق المستخدم ونشط.
5. التاريخ في فترة **مفتوحة** (`assertOpen`) — المغلقة والمقفلة مرفوضة.
6. العملة نشطة؛ السعر لقطة (أو يدوي بالصلاحية)، ويُحفظ مع لقطة سياسة الدقة.
7. **الاتزان بعملة القيد بالضبط** (`decimal.balance`، بلا هامش).
8. **الاتزان بالعملة الأساسية بالضبط** (القسم 6.4).
9. فصل المهام إن كان الإعداد مفعّلًا: من أنشأ لا يرحّل.

### 6.3 القيد العكسي
- من قيد مرحّل غير معكوس ولا هو نفسه عكسي؛ السبب إلزامي.
- السطور نفسها بطرفين متبادلين، **وبالمبالغ الأساسية المحفوظة نفسها** (لا يُعاد التحويل بسعر جديد) ⇒ الصافي صفر بالضبط.
- التاريخ: تاريخ القيد الأصلي إن كانت فترته مفتوحة، وإلا يختار المستخدم تاريخًا في فترة مفتوحة.

### 6.4 العملة الأجنبية بلا فروق تقريب
تحويل كل سطر منفردًا قد يكسر الاتزان بالعملة الأساسية (مثال: 3 سطور × 0.005). الحل: يُحوَّل **المجموع** مرة واحدة `total_base = convert(total, snapshot)`، ثم يُوزَّع على سطور المدين بأوزان مبالغها، وعلى سطور الدائن بأوزانها، عبر `allocate` (أكبر الباقي، حتمية). المجموعان متساويان بالبناء ⇒ القيد متزن بالعملة الأساسية دائمًا، بلا حساب فروق.

### 6.5 الأرصدة في الاستعلامات
- رصيد أي حساب = مجموع حركاته في الأستاذ بالمحرك العشري (`dec_sum`)، لا SUM.
- الحساب التجميعي = مجموع فروعه عبر `path`.
- أول المدة = كل الحركة قبل تاريخ البداية. لأن الإقفال السنوي مؤجل، أول المدة في السنة الثانية سيحمل الإيرادات والمصروفات السابقة إلى أن يُنفَّذ الإقفال (لذلك شرط القرار 8).

| `document_series` | view, create, update, disable |

- الإعداد الجديد `journalSegregatePosting` (افتراضي: معطل).
- كل استعلام يحترم نطاق الفروع؛ «كل الفروع» = المصرح بها فقط (نمط المرحلة 1).
- يُعاد المسح الشامل: صاحب العرض فقط ⇒ كل مسار مغيِّر 403، والقاعدة لا تتغير.

## 8. الواجهة وتجربة الاستخدام

- **شاشة القيد:** رأس (التاريخ، الفرع، العملة، السعر، البيان، المرجع) + جدول سطور يُدار بلوحة المفاتيح بالكامل: Enter ينتقل للخلية التالية ويضيف سطرًا في نهاية الجدول، Tab/Shift+Tab، قائمة ذكية للحساب ومركز التكلفة (بحث بالكود والاسم)، اختصار لحذف السطر وإدراج سطر، Ctrl+S حفظ مسودة، واختصار مستقل للترحيل مع تأكيد.
- **المجاميع والفرق:** تُحسب في الخادم (`POST /api/journal/preview`) لأن الواجهة لا تجري أي حساب على مبلغ (قاعدة مراجعة 0.2.1)؛ تُطلب بعد توقف الكتابة وتعرض: إجمالي المدين، الدائن، الفرق، والمقابل بالعملة الأساسية. زر الترحيل معطل ما دام الفرق ≠ 0 (والخادم يتحقق مستقلًا).
- **دفتر اليومية:** قائمة بتصفية (التاريخ، الفرع، النوع، الحالة، الرقم، الحساب)، فتح القيد، عكسه، طباعة السند.
- **كشف الحساب وميزان المراجعة:** تصفية، توسيع/طي مستويات الشجرة في الميزان، إخفاء الأصفار، الانتقال من سطر الميزان إلى كشف الحساب، طباعة وتصدير Excel.
- عربي/إنجليزي، RTL/LTR، والهاتف بلا تمرير أفقي للصفحة (جدول السطور يتمرر داخل إطاره).

## 9. المتطلبات غير الوظيفية

| المتطلب | المعيار |
|---|---|
| الدقة | لا Number ولا REAL ولا SUM في أي حساب مالي (الاختبارات الآلية القائمة تمتد للوحدات الجديدة) |
| السلامة | الأستاذ إضافة فقط في القاعدة؛ فحص سلامة عند الطلب: كل مستند مرحّل متزن في الأستاذ، والأستاذ يطابق سطور القيود، ولا فجوات في الترقيم |
| الأداء | قياس فعلي على 200,000 و1,000,000 سطر أستاذ: ميزان المراجعة وكشف الحساب. الهدف المبدئي: ميزان مراجعة لسنة كاملة على 200 ألف سطر في أقل من 3 ثوانٍ. إن لم يتحقق: جدول أرصدة مجمّعة لكل (حساب، فرع، فترة) يُحدَّث داخل معاملة الترحيل — **لن يُضاف إلا إذا أثبت القياس الحاجة** |
| التزامن | كاتب واحد (SQLite WAL)؛ معاملة الترحيل قصيرة؛ الاستعلامات خارج معاملات الكتابة |
| الترقية | قاعدة 0.3.1 ببيانات تُفتح بالإصدار 0.4.0 بنسخة احتياطية تلقائية ودون تغيير أي بيانات سابقة |

## 10. الاختبارات (خطة)

| المجموعة | ما سيُثبت |

| الاستعلامات | الميزان متزن دائمًا؛ رصيد كل حساب في الكشف = الميزان؛ التجميعي = مجموع فروعه؛ نطاق الفروع؛ مقارنة `dec_sum` بمرجع مستقل |
| السجلات | بعد أول ترحيل: الحساب والمركز والعملة والسعر والفترة «مستخدمة» (منع الحذف وتغيير الكود)، والعملة الأساسية مقفلة؛ المسودة لا تقفل شيئًا |
| الصلاحيات | المسح الشامل + فصل المهام + الصلاحيات الخاصة |
| الأداء | قياس موثّق في التقرير بالأرقام الفعلية |
| المتصفح | إدخال قيد كامل بلوحة المفاتيح فقط، الفرق من الخادم، منع الترحيل غير المتزن، العكس، الكشف والميزان، العربية والإنجليزية، الهاتف، صفر أخطاء console/CSP |
| الترقية والتثبيت النظيف | من 0.3.1، ومن ZIP في مجلد جديد |
