# تقرير المرحلة 0 — الأساس التقني

## ما تم تنفيذه
- هيكل المشروع ونظام الوحدات (module contract + ترتيب الاعتماديات).
- طبقة SQLite: FK مفعّلة، WAL، synchronous=FULL، معاملات IMMEDIATE مع SAVEPOINT للمتداخلة.
- نظام ترحيلات لكل وحدة مع checksum، ورفض التعديل، ورفض القاعدة الأحدث، وفحص FK بعد الترحيل، ونسخة احتياطية تلقائية قبل ترحيل قاعدة فيها بيانات.
- سجل التدقيق (append-only بقيود triggers داخل القاعدة).
- النسخ الاحتياطي/التحقق/الاستعادة/الاحتفاظ + أوامر CLI.
- خادم HTTP: ترويسات أمان، CSP، حد حجم الطلب، حماية Path Traversal وDNS-rebinding، أخطاء موحدة بلا تسريب، صلاحيات تفشل مغلقًا.
- واجهة أولية (هيكل فقط): اللوجو الرسمي، TAYL والشعار، ساعة وتاريخ وتحية زمنية، قائمة الوحدات الـ22 (معتمة = غير مفعّلة)، رقم الدعم، عربي RTL/إنجليزي LTR مع حفظ اللغة، حالة الخادم والقاعدة.
- مشغّلا ويندوز مخفيان (VBS).

## الأخطاء التي أُصلحت أثناء العمل
1. نطاق إصدار better-sqlite3 في package.json لم يطابق المثبّت (13.x) — صُحّح.
2. نمط تشغيل الاختبارات `tests/` لا يعمل في Node 22 — صُحّح إلى `tests/*.test.js`.
3. اللوجو كان ينضغط إلى ارتفاع صفر في الشريط الجانبي (flex shrink) ولم يظهر — اكتُشف من لقطة الشاشة وصُحّح (`flex: none`).
4. قائمة الوحدات كانت مكررة بين الشريط والصفحة — حُذف التكرار.
5. **تثبيت نظيف من ملف ZIP فشل** (اكتُشف بالتحقق من الصفر): وجود `package-lock.json` يجعل npm يحاول تجميع better-sqlite3 من المصدر (يحتاج إنترنت ومترجم C++) متجاهلًا أن الحزمة تشحن ملفات جاهزة. صُحّح بملف `.npmrc` (`ignore-scripts=true`) وتثبيت الإصدار بدقة `13.0.3`؛ والتحقق النهائي: فك ZIP في مجلد جديد ← `npm ci` ← 46/46 ناجح.
6. حقل `engines` كان `>=20` والصحيح `>=22` (متطلب better-sqlite3 13).

## المشكلات المتبقية / ملاحظات
1. **مشغّلا VBS لم يُختبرا على ويندوز** (بيئة الاختبار لينكس). يلزم اختبارهما على جهازك.
2. **better-sqlite3 على ويندوز:** تأكدت من وجود الملف الجاهز `win32-x64.node` داخل الحزمة، لكنه لم يُشغَّل على ويندوز فعليًا. كذلك **يلزم Node 22 أو أحدث** (يشمل Node المحمول في حزمة التسليم).
3. **ملف اللوجو** صورة مستطيلة تحوي خلفية بطاقة معدنية وليست شعارًا بخلفية شفافة. استُخدم كما هو دون تعديل (حسب التعليمات)، لكنه سيظهر كبطاقة داخل التقارير والطباعة. يُنصح بتزويدي بنسخة PNG شفافة أو SVG للتقارير.
4. لا توجد مصادقة بعد (المرحلة 1)؛ أي مسار يطلب صلاحية يُرفض تلقائيًا إلى حين تفعيلها.
5. الاستعادة عبر CLI فقط (والبرنامج مغلق)؛ واجهتها وجدولة النسخ ضمن وحدات لاحقة.
6. مسار البيانات الافتراضي داخل مجلد البرنامج (انظر المخاطر).
7. لا بيانات تجريبية في أي قاعدة؛ الاختبارات تعمل على قواعد مؤقتة تُحذف.
