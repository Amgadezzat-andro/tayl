## 2. مراجعة تصحيح سعر الصرف

### المشكلة
- `DELETE /api/currencies/rates/:id` كان يحذف السطر فعليًا. حدث التدقيق يحفظ القيمة المحذوفة، لكن جدول الأسعار نفسه لا يعرف أن سعرًا كان ساريًا ثم أُزيل، ولا لماذا.
- القيد `UNIQUE (currency_id, rate_type, effective_date)` جعل الحذف الطريق الوحيد لتصحيح سعر في نفس التاريخ.
- حذف آخر سعر كان يعيد فتح تغيير العملة الأساسية (يخالف القرار 1).

### الحل: سلسلة تصحيحات إضافة فقط
ترحيل جديد `currencies/0002_exchange_rate_corrections.sql` (الترحيل 0001 لم يُعدَّل):

```
exchange_rates (… الأعمدة السابقة كما هي …,
  entry_kind    'original' | 'correction' | 'void',
  supersedes_id → exchange_rates(id)  UNIQUE,   -- السطر الذي يحل محله
  reason        إلزامي (3–500) لكل تصحيح أو إلغاء)
```

| القاعدة | أين تُفرض |
|---|---|
| لا تعديل لأي سطر | trigger (قائم) |
| **لا حذف لأي سطر** | trigger جديد + لا مسار حذف في الـ API |
| سلسلة واحدة لكل (عملة، نوع، تاريخ) | فهرس فريد جزئي على السطر الأصلي |
| السلسلة خطية (كل سطر يُستبدل مرة واحدة) | `UNIQUE (supersedes_id)` |
| التصحيح لنفس العملة والنوع والتاريخ فقط | trigger |
| السبب إلزامي للتصحيح والإلغاء، والإلغاء بلا قيمة | `CHECK` |

- **السعر الساري** لكل تاريخ = رأس السلسلة (لا سطر يحل محله) ما لم يكن إلغاءً. `rateSnapshot()` والقائمة وآخر سعر في شاشة العملات تستخدم هذه القاعدة وحدها.
- **التصحيح** `POST /api/currencies/rates/:id/correct {rate, reason}`: قيمة جديدة بنفس قواعد الإدخال (موجب، 12 خانة، لا تقريب صامت)، ورفض القيمة المطابقة (`NO_CHANGE`).
- **الإلغاء** `POST /api/currencies/rates/:id/void {reason}`: لسعر أُدخل بتاريخ أو نوع خطأ؛ السعر الساري يعود لما قبله. ويمكن «تصحيح» الإلغاء لاحقًا بقيمة.
- تصحيح سطر صُحِّح من قبل ⇒ `RATE_SUPERSEDED` مع رقم السطر الحالي؛ وإضافة سعر لتاريخ له سلسلة ⇒ `RATE_EXISTS` مع رقم السطر الحالي (لاستخدام التصحيح).
- **التدقيق:** `exchange_rate.corrected` / `exchange_rate.voided` بالتفاصيل: العملة، النوع، التاريخ، السطر المستبدل، من ← إلى، السبب، والمستندات المستخدمة له.
- **المستندات القائمة لا تتغير:** المستند يحفظ لقطة السعر (القيمة نفسها + رقم السطر)، فالتصحيح يسري على المستندات الجديدة فقط. معالجة مستند استخدم سعرًا خاطئًا تكون بقيد عكسي في المرحلة 3، لا بتغيير السعر خلفه. الرد يعرض `usedBy` للعلم.
- **الصلاحيات:** التصحيح والإلغاء بـ `currencies.manage_rates` (نفس الإضافة)؛ عرض السجل بـ `currencies.view`.
- **الواجهة:** زر «حذف» أُزيل. لكل سعر: «تصحيح» (السعر الصحيح + السبب)، «إلغاء السعر» (السبب)، «سجل التصحيحات» (كل الأسطر بالترتيب: الحركة، السعر، السبب، الحالة). الحالة: ساري / حلّ محله تصحيح / ملغى.
- **الترقية:** كل الأسعار السابقة تصبح `original` بنفس المعرّف والقيمة والتاريخ ومن أنشأها. حدث `exchange_rate.deleted` القديم (إن وُجد في سجل التدقيق) ما زال مترجمًا للعرض.
